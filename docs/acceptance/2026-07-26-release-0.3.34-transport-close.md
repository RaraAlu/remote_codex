## 问题与修复

`VsCodeRemoteExecutor.close()` 会对活动 socket 调用 `destroy()`。请求此前只监听
`error` 和 `end`，而该本地关闭路径只触发 `close`，导致活动 Promise 永久悬空。
问题复现脚本在请求发出后关闭执行器，Node 最终以“未终结的顶层 await”退出码 13
结束；远端原文件仍保持原始哈希且临时写入文件为 0，但调用方无法得到终态。

修复为请求增加一次性 `close` 监听，并复用既有断线错误和副作用恢复语义：

- 无副作用请求仍可按既有策略恢复；
- 有副作用请求不盲目重放，返回带幂等键的 `RESULT_UNKNOWN`；
- 所有请求终态仍由同一个 `finish()` 保护，避免多事件重复完成。

新增单元测试在服务端收到副作用请求后主动关闭本地执行器，确认请求明确终结为
`RESULT_UNKNOWN`，恢复次数为 0。

## 结论

VS Code transport 本地关闭导致活动请求永久悬空的问题已经由 `0.3.34` 修复，并在精确
安装候选和真实 `g1_1` transport 上完成写入中断、文件完整性、超限拒绝、固定探针及
后置清理闭环。该提交可以作为独立、已验证的 Linux 行为修复保留。它不是 `0.4.0`
发布通过声明；README 中剩余官方任务、生命周期、故障矩阵、MCP、最终清理和 Windows
范围仍按代办继续。
