## 问题与修复

- Remote SSH thread 的 Core `cwd` 必须是受限的本机控制目录，不能直接使用远端 POSIX
  路径；旧实现让所有远端根共享同一个控制目录，因此官方 `thread/list` 无法按工作区
  区分历史。
- `0.3.45` 对规范化的 `host + workspaceRoot` 计算稳定 SHA-256 摘要，并在
  `remote-control/<摘要>` 下为每个远端根创建独立控制目录。父目录权限为 `0700`，
  实际 Core 工作目录为 `0500`。
- VS Code Remote SSH 客户端的 `thread/list` 精确查询当前控制目录；start、resume 和
  turn 使用同一目录。逻辑远端根仍由 `runtimeWorkspaceRoots`、开发指令和 Bridge 工具
  承载，不伪造 VS Code workspace URI。
- 旧共享控制目录中的历史没有可靠的远端身份，因而不并入新列表；显式 thread ID 恢复
  和外部客户端全局查询能力保持不变。
