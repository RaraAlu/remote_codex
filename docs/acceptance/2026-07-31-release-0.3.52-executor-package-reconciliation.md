## 根因与实现

- 旧 Executor 能按能力集合通过 ping 时，Controller 会直接复用它；Windows 远端因此可能
  长期运行旧包，且旧 ping 的 `executorVersion` 来自编译常量，无法证明实际安装清单版本。
- Executor 现在从 `ExtensionContext.extension.packageJSON.version` 上报 `packageVersion`，
  同时以该值作为运行版本；Controller 每次初始化都将它与内嵌 Executor 配套版本精确比较。
- 缺失、较旧或较新的包版本都触发内嵌 VSIX 安装。安装复用 `vscode.workspace.fs` 和
  `workbench.extensions.installExtension`，不建立第二条 SSH 认证链路；安装完成后自动重载窗口。
- 包版本同步与能力准入分离。兼容旧 Executor 的同步失败只记录诊断并继续使用现有链路，
  不会仅因版本值不同进入 `incompatible`。
- 当前 Windows 内置 app-server 将 POSIX 远端根作为 `runtimeWorkspaceRoots` 反序列化时返回
  `Invalid request: AbsolutePathBuf deserialized without a base path`。Shim 现在在 Windows
  使用真实本机控制目录作为 runtime root；远端 POSIX 主根仍通过 Bridge 策略、附加上下文和
  动态工具传递，不改写或伪造 VS Code 工作区 URI。
- VS Code 的全局 `extensions.onDidChange` 会因无关扩展事件反复初始化 Controller。激活入口
  现在记录官方 `openai.chatgpt` 与 Remote Executor 的安装路径/包版本指纹，仅在指纹实际变化
  时重新初始化。

## 遗留风险与结论

- Windows Node SEA 构建仍会输出 `signature seems corrupted`：`postject` 将 SEA blob 注入复制的
  Node 可执行文件后，原 Node 签名不再适用。最终 Shim 已通过内容哈希、连续冒烟和真实 Remote SSH
  链路验证；本记录不将其表述为 Authenticode 已签名。若发行策略要求 Windows 代码签名，仍需在
  注入完成后另行签名。
- 当前结论：Windows Executor 配套版本自动同步、重载、官方任务创建和远端项目操作目标
  通过；Windows 自动化、Shim 冒烟和构包门禁也已关闭。Linux 结果按用户确认另行保留。
