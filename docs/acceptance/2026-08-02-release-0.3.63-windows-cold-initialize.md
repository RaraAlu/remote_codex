## 问题与实现

- `0.3.62` 中外部 MCP 固定使用 `clientInfo.name=codex_vscode_bridge_mcp`。同一网关使用
  中性名称只需 `5–6 ms`，固定名称连续两次约 30 秒超时，原始 WebSocket 探针超过 40 秒
  仍无初始化响应。
- 仅更换静态名称不能稳定消除重载后的第一条次级连接停滞；因此最终实现为每连接生成
  `codex_remote_bridge_external_client_<uuid>`，重试也生成新身份，避免连接身份复用。
- 共享网关先把 `initialize` 交给官方 app-server，再把匹配唯一身份的连接标记为
  `external-mcp`，从而保留审计归属但不让分类逻辑参与上游初始化。
- 外部会话描述符只在主 VS Code 客户端收到成功 `initialize` 响应后发布，避免客户端连接
  到尚未完成主握手的网关。
- 客户端首轮初始化使用最多 1 秒的冷探针；仅当 `initialize` 超时时关闭该连接、等待
  50 ms，并在原总超时预算内以新身份重试一次。连接错误、协议错误和非初始化请求不会
  被该规则掩盖。

  `2026-08-01T21:35:13.034Z` 把 `chatgpt.cliExecutable` 迁移到新的内容寻址 Shim 路径，
  随即又自动请求一次窗口重载。
