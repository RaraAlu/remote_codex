## 真实问题复核

- 当前 `g1_1` 窗口使用 Controller/Shim `0.3.45`，工作区为
  `/home/unitree/mimiclite-sim2real`。
- `shim.start` 审计明确记录 `remoteMcpServers=["codegraph"]`，app-server 参数把
  `codegraph serve --mcp --path /home/unitree/mimiclite-sim2real` 改写为带
  `codegraph-all-tools-v1` 的 Bridge MCP relay。
- `code --status` 同时确认远端 Workspace Extension Host 中存在绑定该工作区的
  Codegraph MCP 进程。因此这些 Codegraph 工具已经在远端运行，并不需要
  `target/rootId` 参数。
- 当前官方对话却先后宣称“Codegraph MCP 没有 target/rootId，无法确认访问远端
  索引”，随后改用 `remote_exec` 调用 Codegraph CLI。根因不是远端能力缺失，而是
  Bridge 只注入了本地 MCP 的限制，没有把本次 app-server 的实际远程路由身份提供给
  模型。

## 修复

- `routeRemoteMcpServers` 的实际 `remoteMcpServers` 结果由 Shim 入口传给
  `SharedAppServer`、每个 `ShimProxy` 和请求改写器。
- thread start、resume、fork 与每轮 `additionalContext` 都明确列出当前远程路由服务。
- 策略说明列出的服务已绑定远端主根，其工具可直接调用，Schema 有意不包含
  `target/rootId`；当 `codegraph` 在列表中时，优先使用远端 MCP 的
  explore/node/impact。
- 只有 Codegraph 没有被远程路由时，才通过 `remote_exec` 探测
  `codegraph --version` 并使用远端 CLI；未列出的本地 MCP 继续遵守原有根身份限制。
