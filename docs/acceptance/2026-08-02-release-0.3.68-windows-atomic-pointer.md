# Bridge `0.3.68` Windows launcher 原子指针验收

日期：`2026-08-02`

执行人：Codex 自动化验证 + 用户手动窗口重载

## 范围

- 修复稳定官方 launcher 更新 `current.json` 时，Windows 短暂文件占用导致的 `EPERM`。
- 仅修改 Controller 的 launcher 安装逻辑；Remote Executor 保持 `0.2.21`，Shim 协议和
  内容不变。
- 不把远端 VS Code Server 的旧代理环境慢启动计入本目标通过条件，该问题继续由独立的
  Windows 更新环境门禁跟踪。

## 现场故障

`0.3.67` Extension Host `PID 281848` 于 `07:39:50.105` 更新稳定 launcher 指针时，
Windows 返回：

```text
EPERM: operation not permitted, rename 'current.json.<pid>.<uuid>.tmp' -> 'current.json'
```

同一进程稍后能够写入目标，说明这是短暂占用而不是目录权限永久失效；但首次失败已触发
用户可见错误，并使官方 launcher 等待匹配当前 Extension Host 的指针。

## 实现与自动验证

- `current.json` 和 `launcher.json` 仍先写同目录临时文件再原子替换。
- 仅在 Windows 且错误码为 `EPERM`、`EACCES` 或 `EBUSY` 时重试，延迟序列为
  `10/25/50/100/200/400/800/1000 ms`，总等待上限为 `2,585 ms`。
- 非 Windows、其他错误码以及重试耗尽继续抛出原错误；`finally` 继续清理临时文件。
- 定向测试：`test/shim-executable.test.ts` 9 项通过，覆盖短暂 `EPERM` / `EBUSY` 恢复和
  永久 `EPERM` 不被吞掉。
- `npm run check` 通过：67 个测试文件、335 项测试通过；类型检查、构建、Shim 冒烟和
  Windows x64 构包全部成功。
- 安装产物：`codex-remote-bridge-0.3.68-win32-x64.vsix`；Executor 产物仍为
  `codex-remote-bridge-executor-0.2.21-linux-x64.vsix`。
