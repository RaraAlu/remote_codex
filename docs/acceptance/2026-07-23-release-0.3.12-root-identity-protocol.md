## 问题与实现边界

- 现有 `remote_*` 工具只隐式依赖 `workspaceRoot`，结果只有 `remoteCwd`，不能为后续双端
  读取稳定区分根 ID、目标端和主次角色。
- 每个远端工具 Schema 现在接受可选 `target="remote"` 和 `rootId`；省略时仍选择唯一
  `remote/primary`，保持已有调用兼容。
- 工具结果增加 `rootId`、`target`、`rootRole` 和 `rootPath`；审计在顶层记录同一组
  根身份。当前远端成功结果继续保留 `remoteCwd`。
- 配置中存在的 `local/secondary` 根尚未开放。绕过 Schema 直接请求本地根时，
  Router 返回 `COMMAND_DENIED`，不调用远端执行器，结果不暴露本地 `rootPath`；内部审计
  仍记录被拒绝的授权根身份。
- 本目标不实现本地目录选择、本地执行器或双端路由，不改变 Remote Executor 协议，也
  不把 `local` 写入当前远端工具的公开目标枚举。

## 遗留风险与结论

- 本地授权根目前只能存在于配置中，仍没有用户选择、持久授权、撤销和本地只读执行器。
- 当前公开工具名仍为 `remote_*`，只暴露 `target="remote"`；双端统一工具和原生 UI
  投影等待阶段 3 后续提交。
- 候选 VSIX 安装后的真实官方任务、Remote SSH 显式根选择及 Windows x64 实机待补测。
- 最终结论：双端只读所需的根身份协议基础已建立，并对尚未实现的本地目标失败关闭；
  不据此声明本地读取或完整双端能力。
