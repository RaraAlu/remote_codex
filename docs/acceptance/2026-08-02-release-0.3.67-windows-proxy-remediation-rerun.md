## 根因补充

- 两轮远端 Extension Host 中，内置 `GitHub.copilot-chat` 分别在 `07:32:37.925` 和
  `07:32:52.589` 激活；Executor 的 ping 激活直到 `07:32:42.927` 和 `07:32:57.907`
  才开始，分别排队约 5.0 秒和 5.3 秒。
- 第二轮远端日志再次记录连接 `127.0.0.1:32081` 代理失败。
- `/etc/environment` 和 `/etc/profile.d/bigbear-proxy.sh` 的活动代理配置已清理，但当前
  VS Code Server 进程自 `06:44:06` 起运行，早于 `07:28` 左右的配置清理；其进程环境仍
  持有大小写两组 HTTP/HTTPS/ALL proxy，全部指向 `127.0.0.1:32081`。
- 普通窗口重载重建了 Remote Extension Host，却复用了上述 VS Code Server，所以不能刷新
  继承环境。这也解释了首轮曾短暂达到 `1,182 ms`，后续仍可再次触发代理等待。

## 结论与下一步

本轮不通过连续稳定门禁，计数由 1/3 重置为 0/3。下一步不是继续普通重载，而是一次性
终止该主机上的远端 VS Code Server 并重新连接，使新 Server 在无失效代理的环境中启动；
随后重新执行三次普通窗口重载，逐次确认无语言包更新、无 Remote Extension Host 无响应、
无额外自动重载，且 Executor 能力探测低于 2 秒。
