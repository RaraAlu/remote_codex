## 变更与边界

| 项目 | 内容 |
| --- | --- |
| Bridge 版本 | `0.3.26` |
| 基线提交 | `3f82378` |
| Remote Executor | `0.2.13`；诊断协议 8，未改变 |
| 实现目标 | 为缺少后续动态工具的历史对话提供显式完整能力新对话入口 |
| 触发项 | Controller/Shim、官方 app-server 线程创建、外部 MCP、权限继承 |
| 声明范围 | Linux 自动化、Linux 原生候选包、`g1_1` 最终候选重载与单样本实机；完整人工门禁待补测 |

- 外部 MCP 新增 `vscode_codex_start_conversation`。调用方必须选择活动 Bridge
  `sessionPid`，Shim 先调用 `thread/start`，再在新 thread 上调用首个 `turn/start`；
  当前动态工具因此在 thread 创建时注入。
- 历史 thread 的工具集合仍保持创建时快照。Bridge 不伪造工作区 URI，也不把新增工具
  塞入官方 app-server 已加载的旧 thread；需要新能力时显式新建对话。
- `permissionMode=full-access` 显式发送
  `permissions=full-access` 和 `approvalPolicy=never`，项目操作由现有 Bridge 安全边界
  自动放行并审计；`on-request` 不提升官方默认权限。
- 官方 app-server 不支持对临时 thread 执行完整历史读取，因此候选不公开无法观察和
  清理的 ephemeral 选项。`0.3.24`、`0.3.25` 是本目标的废弃中间候选，
  `0.3.26` 是首个保留版本。

### 取消、幂等与结果恢复

- 在既有单次取消基础上，新增两个附着 CLI 前台取消样本。`turn/interrupt` 分别耗时
  19 ms 和 54 ms，`remote_exec` 分别在 69 ms 和 96 ms 返回 `CANCELLED`；每次随后

  标记不存在。另一次过早 interrupt 的 `cancelledCalls=0` 不计为等待审批取消通过；
  “审批等待中取消”仍待官方 UI 复核。
- 真实传输恢复使用本地中间代理只丢弃 Shim 侧响应、保持 Controller 到 Remote
  Executor 的上游 socket 存活。completed、failed、cancelled 和未送达 unknown 各跑
  5 次：completed 均返回原 stdout 和 `idempotencyOutcome=replayed`；failed 均保留
  `PATH_OUTSIDE_ROOT`；cancelled 均确认取消并保留 `CANCELLED`；unknown 均返回
  `RESULT_UNKNOWN`。每个 completed 样本恢复前都观测到至少 3 次 `running`。
- 另跑 5 次“首个 `resultStatus` 响应丢失”，后续查询全部恢复 completed 原结果。

  `joined`；同键改参 5/5 返回 `PROTOCOL_MISMATCH`。
- 直接关闭真实 Unix transport socket 会按设计触发服务端取消；首轮错误注入的运行
  请求因此全部进入 `cancelled`，不能充当结果丢失恢复证据。上述代理批次用于准确区分
  “调用方主动断开”与“响应在返回途中丢失”。
