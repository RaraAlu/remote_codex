## 实现与结果语义

- `RemoteToolCallCoordinator` 以 `threadId + turnId + callId` 协调执行，并为活动调用保存
  `AbortController`。客户端转发 `turn/interrupt` 前，Shim 取消同一 thread/turn 的
  活动调用并记录 `remote_tool.cancel` 审计。
- 等待官方命令审批时收到中断会撤销等待、返回 `CANCELLED`，且不会启动远端进程。
- `VsCodeRemoteExecutor` 在请求已经发送后另开受认证 transport 请求，以原请求 ID
  作为 `operationId` 调用 `cancel`；它等待 Remote Executor 的原请求返回明确
  `CANCELLED`，而不是仅关闭本地 socket。
- Controller 在调用方 socket 意外断开或自身关闭时也会向 Remote Executor 请求取消。
  无法确认取消的有副作用请求仍返回 `RESULT_UNKNOWN`，不会本地回退或自动重放。
- Remote Executor 以 host、workspace 和 operation ID 绑定活动 `AbortController`。
  POSIX 命令使用独立进程组，先发送 `SIGTERM`，一秒后仍未结束则发送 `SIGKILL`。
- OpenSSH 回退仍只能终止本地 SSH 进程，不能确认远端进程树；Windows 当前只终止直接
  子进程。两条路径均未声明完整进程树取消能力。

## 遗留风险与结论

- 待补测：安装当前候选后，从官方 Codex UI 启动长命令并执行取消，核对 Codex 日志、
  Bridge 审计、Remote Executor 返回、取消确认耗时和远端进程树。
- 待补测：Controller socket 断开、窗口关闭和 Extension Host 退出三种方式的遗留进程。
- 已知限制：OpenSSH 回退没有远端 operation 状态；Windows 没有完整进程树终止实现。
- 已知限制：跨重连幂等账本、`result-status` 查询和断线恢复尚未实现，未知结果不得
  自动重放。
- 最终结论：运行中取消的默认 VS Code Remote 协议闭环和 POSIX 进程组终止已通过
  自动化与构包验证；在真实 Remote SSH 和 Windows 实机完成前保持自动化候选声明。
