## 实现与安全边界

- Shim 写入 v2 描述符，新增规范化 `executablePath`，并以进程 wall clock 与 uptime 计算
  真实启动时间；排序和会话 PID 语义保持不变。
- Windows 以一次隐藏 PowerShell 进程表探测批量读取 PID、路径和启动时间；Linux 使用
  `/proc/stat`、`getconf CLK_TCK`、`/proc/<pid>/stat` 和 `/proc/<pid>/exe` 得到同等身份。
- v2 描述符使用 2 秒启动时间容差并要求路径相等；v1 兼容读取要求描述符写入时间位于
  进程启动后的 30 秒内，且实际进程必须是 Shim 或 Node 可执行文件，避免把后来复用 PID
  的新进程当作活动会话。
- 已退出或身份不匹配的描述符先原子移入随机隔离名，并在删除前比较原始内容；若同一 PID
  路径已被新进程重写，则恢复新内容而不覆盖并发创建的描述符。Token 文件不随发现清理，
  避免 PID 复用竞态删除新进程刚写入的凭据。
- 整体进程身份探测失败时退回既有 PID 存活判断；单个活动 PID 暂时没有身份时只从列表
  隐藏、不删除其描述符。外部网关仍只监听 loopback，并继续校验 PID 对应的 Token 路径。
