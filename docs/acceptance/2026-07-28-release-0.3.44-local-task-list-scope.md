## 问题与修复

- 官方 app-server 的 `thread/list` 支持精确 `cwd`，但普通本地窗口此前透传全局查询，
  因而会显示其他本地工作区以及 Bridge Remote SSH 验收任务。
- 首个候选通过 Extension Host 子进程环境传递工作区根。真实窗口重载后仍复现全局
  列表，确认官方 app-server 可能早于 Bridge Controller 激活，环境继承存在启动竞态。
- 最终方案由 Controller 以 Extension Host PID 保存仅含版本和绝对工作区根的最小
  上下文。Shim 不在启动时等待，而是在每次 VS Code `thread/list` 请求到达时动态读取。
- 过滤只作用于官方 VS Code 本地客户端。外部 CLI/MCP 仍可查询全局任务；Remote SSH
  会话不读取本地窗口上下文，也不伪造远端工作区 URI。
