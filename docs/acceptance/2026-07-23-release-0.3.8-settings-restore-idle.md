## 问题与修复边界

- 真实执行 `Codex Bridge: Restore Official Codex Settings` 后，原始设置中没有
  `chatgpt.cliExecutable` 和 `remote.extensionKind.openai.chatgpt`，因此 Remote SSH
  窗口按预期不再显示 Codex UI，远端也没有安装 Codex。
- `0.3.6` 在重载后仍先校验官方扩展。恢复状态下官方扩展不在当前 UI Extension Host
  可见范围，Bridge 因而错误提示官方 OpenAI Codex 未安装。
- 首个 `0.3.7` 候选仍把默认启用的外部 CLI 对接视为官方运行时校验触发项；实机复现后
  立即废弃，变更后的行为改用 `0.3.8`，没有复用已运行版本。
- `0.3.8` 将初始化意图拆分为托管 Shim 修复、外部 CLI 对接和 Remote SSH 自动连接。
  只有托管 Shim 修复或 Remote SSH 自动连接需要官方运行时；外部 CLI 对接可独立完成。
- 本目标不在远端安装 Codex，不改变远端执行、Shim 协议、MCP 路由或外部网关行为。

## Linux x64 实机证据

- 恢复前活动 Bridge 为 `0.3.6`，状态为 `ready`。恢复命令写入
  `ready -> disabled` 和 `bridge.stop=succeeded`，并删除当前窗口会话。
- 恢复后 `chatgpt.cliExecutable` 不存在，`remote.extensionKind` 只保留原有
  `pub.name: ["ui"]`，`autoInitialize=false`，设置备份已清空。
- 用户重载后，旧 Shim PID `502998` 及其描述符、外部令牌和上游令牌全部消失。
  没有新的窗口会话、网关描述符、Shim、官方 app-server 或远端 Codex。
- `0.3.8` 重载日志两次记录
  `automatic Remote SSH initialization disabled; bridge remains idle`；外部 CLI 集成分别
  完成更新和无变化自检，没有再次校验不可见的官方扩展。
- 仍运行的 `0.3.4 external-mcp` 由重载前已存在的外部 CLI 进程持有，不属于当前窗口
  或本次恢复产生的新进程，本目标不主动终止用户的独立 CLI 会话。

- 设置恢复后 Codex UI 按原始配置从 Remote SSH 窗口消失；重新配置 Bridge 并恢复本地
  UI Extension Host 路由需要单独实机验证。
- 独立执行 `Codex Bridge: Stop`、Extension Host 完全退出、relay/MCP 子进程归零、
  历史 thread 恢复和 Windows x64 实机仍待补测。
- 最终结论：`0.3.8` 的设置恢复与停用空闲态目标在 Linux x64 真实 Remote SSH 窗口
  通过；远端没有安装或运行 Codex，完整生命周期与双平台支持仍受上述缺口限制。
