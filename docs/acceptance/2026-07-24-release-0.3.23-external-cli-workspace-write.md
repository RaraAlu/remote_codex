日期：2026-07-24

执行人：Codex（实现、自动化、Linux 原生构包与审计检查）

复核人：待补测（`test_40` / Zklab 真实双客户端、权限撤销、Windows x64）

## 变更与边界

| 项目 | 内容 |
| --- | --- |
| Bridge 版本 | `0.3.23` |
| 基线提交 | `f011668` |
| Remote Executor | `0.2.13`；诊断协议 8，未改变 |
| 实现目标 | 外部 CLI 项目写入、权限继承、因果来源和 operation ID 审计 |
| 声明范围 | Linux 自动化与 Linux 原生候选包；真实 Remote SSH 和 Windows 实机待补测 |

- 外部 CLI 发起的 `workspace_write_file` 继续经过既有动态工具路由、已配置目标端、
  `expectedHash`、原子替换和幂等协调器；没有增加 SSH 或本地文件写入旁路。
- thread 的 Codex 权限仍是唯一审批来源。`full-access` 自动放行；其他模式继续使用
  官方 `item/commandExecution/requestApproval`。
- 共享网关按 thread/turn 保存实际发起客户端。官方 app-server 即使把同一工具请求
  广播给 stdio 与外部连接，最终操作和审批审计仍归因到发起 turn 的客户端。
- 外部请求记录连接实例、来源类型、operation ID、method 和 thread/turn/call 关联字段，
  并记录开始、成功、失败或断开取消；不记录对话输入、文件正文或凭据。
- `expectedTurnId` 原值透传，Bridge 不增加单写者租约；官方冲突响应仍由原连接返回，
  无 ID 事件继续按既有规则去重广播。

## 人工补测

人工步骤统一保留在 `docs/manual-acceptance-backlog.md`，本目标不提前执行：

- M10：在 `test_40` / Zklab 的同一真实 thread 中，从 CLI 发起带 `expectedHash` 的替换
  写入，核对 VS Code UI、远端文件、审批、来源和 operation ID。
- M10：覆盖 `expectedTurnId` 冲突、CLI 中途断开、网关重启、过期描述符和权限撤销；
  `full-access` 不应追加审批，其他模式不得升权。
- M01、M03、M06、M07、M08、M09：安装最终候选后统一完成 Linux/Windows、固定探针、
  断线恢复、生命周期、敏感信息和日志审计门禁。

最终结论：外部 CLI 项目写入复用既有安全写入链、权限继承、因果来源和请求生命周期
审计已完成自动化；真实 `test_40` / Zklab 双客户端闭环与 Windows x64 仍为
`待补测`，因此不据此声明完整发布支持。
