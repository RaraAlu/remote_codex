## 实现与安全边界

- Shim 公开 `workspace_read_file`、`workspace_list_directory`、`workspace_list_tree`、
  `workspace_search` 和 `workspace_git_status`。省略目标时仍选择唯一远程主根；本地
  请求必须同时指定 `target="local"` 和当前配置中的次级根 ID。
- 本地请求通过既有窗口级认证 socket 回到 Controller；Controller 核对活动 Remote
  SSH 会话、主机、远程工作区、会话配置和实时授权后，才调用有界本地执行器。请求
  不会转发到 Remote Executor，也没有任意本地命令入口。
- 远程请求继续使用现有 Remote Executor；用户明确选择 `openssh` 时只回退远程目标，
  本地目标因没有 Controller workspace client 而失败关闭，不会启动第二次认证。
- 读取、目录、目录树、字面搜索和固定只读 Git 状态共享 `WorkspaceExecutor` 契约。
  结果、逐轮上下文、审计和原生命令项保留目标端、根 ID、主次角色、规范化路径及正确
  `cwd`。
- Remote Executor 继承的远端搜索从正则匹配收紧为大小写敏感的字面匹配，因此按实现
  变更独立升级到 `0.2.9`；ping 能力集合和请求协议形状没有变化。
- 旧 `remote_*` 只读工具名继续接受历史会话调用，但固定只允许远程主根；`remote_exec`
  仍是唯一命令工具且只允许远程主根。

## 遗留风险与结论

- 候选 VSIX 尚未安装到真实 Remote SSH 窗口；本地与远程同名文件交替读取、官方 UI
  命令项观感、Codex 日志和 Bridge 审计的联动证据待补测。
- 本目标只开放只读操作；双端写入、哈希冲突、原子替换、审批和跨重连幂等仍未实现。
- Linux Remote SSH 候选安装回归和 Windows x64 Extension Host 实机仍待补测。
- 最终结论：统一双端只读路由已完成自动化和双平台构包验证，不据此声明真实窗口或
  双端写入能力已经闭环。
