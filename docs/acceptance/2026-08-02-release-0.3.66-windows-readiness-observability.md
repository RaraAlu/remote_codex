## 实现与安全边界

- `connecting` 状态下显式显示 `waiting for Remote Extension Host` 或
  `probing remote workspace`；远端 transport 已可用但 app-server 未初始化时继续使用既有
  `degraded` 门槛，不提前伪报 `ready`。
- Executor 能力探测超过 2 秒时写入一次慢启动日志，即使当前 VS Code command Promise
  仍在等待 Remote Extension Host；探测完成后记录次数、总耗时和慢启动标记。
- 新增 `executor.readiness` 审计；诊断的 `bridge.startup` 同步报告当前阶段、阶段起点和
  最近一次 Executor 探测指标。审计不记录密码、Token、远端命令正文或环境快照。
- Remote Executor 保持 `0.2.21` / 诊断协议 13。本目标不修改远端扩展，不应触发
  Executor 安装或升级重载。

## 遗留风险与结论

- 待补测：快启动路径已有自动化，但本记录只量化一次真实慢启动；完整发布门禁仍要求冷、热
  启动各 3 次以及 Linux 原生对照。
- 已知限制：Bridge 不能在 Remote Extension Host 尚未响应时诚实地声明远端能力已
  `ready`；本目标提供真实阶段与耗时，不伪造可用性，也不修改 VS Code 的远端扩展调度。
- 当前结论：Windows x64 冷启动就绪可观测性逐目标验收通过；不外推完整发布支持。
