## 问题与修复

- `0.3.42` 先按当前目录查找活动 thread，但目录无匹配时仍会在全部活动描述符中回退。
  其他 VS Code 工作区只要同时存在多个活动 thread，普通 `codex` 就会误报多会话歧义；
  只有一个其他工作区 thread 时还会错误附着该 thread。
- `0.3.43` 保留当前目录唯一匹配和同目录多匹配失败关闭，只删除跨目录回退。目录无匹配
  时返回 `null`，由托管入口透传保存的官方 Codex 可执行文件。
- 显式 `codex-vscode --session-pid <pid>` 的选择、鉴权和附着路径没有改变。
