## 问题证据

- 原 `BridgeController.#connect` 在 Remote Executor `probe()` 成功后立即进入 `ready`，
  没有观察官方 `chatgpt.cliExecutable` 是否成功启动 Shim。
- 故障窗口中状态栏为 `ready`，但官方日志显示 Shim 因找不到 Node 退出 `127`，
  app-server stdin 已销毁，Codex Webview 持续加载。
- 设置写入后 `workbench.action.reloadWindow` 终止当前 Extension Host 时，还可能记录
  `official Codex settings bootstrap failed: Canceled`，该信息不代表配置失败。

## 修复

- Shim 按 `host + workspaceRoot` 写入权限受限、原子替换的运行状态；内容只包含启动器
  类型和路径、PID、时间、退出码、initialize 状态与错误，不包含 Token、端点或环境值。
- `SharedAppServer` 启动时记录 Shim 存活；只有 VS Code stdio 客户端的 `initialize`
  成功响应才记录 app-server 初始化；退出和启动异常会保留最后退出码或错误。
- Controller 远端探针成功后读取状态和检查本机 PID。未初始化时进入 `degraded` 并显示
  “remote ready; Codex starting/waiting/failed”，后台心跳确认初始化后才进入 `ready`；
  心跳丢失会从 `ready` 返回 `degraded`。
- Diagnostics 增加 `nodeExecutable`、`shimStarted`、`shimPid`、
  `shimLastExitCode`、`appServerInitialized` 和 `appServerLastError`。
- 窗口重载命令返回精确 `Canceled`/`CancellationError` 时按正常 reload 生命周期处理；
  其他错误继续失败关闭并报告。
