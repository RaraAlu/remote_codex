## 实现与结果语义

- Shim 以 `threadId + turnId + callId` 的 SHA-256 摘要生成稳定幂等键。同一官方工具
  调用即使重新送达，也使用相同键；不同 turn 或 call 不共享键。
- Remote Executor 以 host、规范远端工作区和幂等键作为账本键，并以请求参数和策略
  的规范化摘要校验请求身份。同键同参数在运行中加入原 Promise，结束后重放原结果；
  同键不同参数以 `PROTOCOL_MISMATCH` 失败，副作用不会再次启动。
- `resultStatus` 返回 `running`、`completed`、`cancelled`、`failed` 或 `unknown`。
  执行结果与错误详情同时记录 `executed`、`joined` 或 `replayed`，便于 Bridge 审计
  区分首次执行和去重结果。
- 账本默认最多保留 256 项、15 分钟和 64 MiB。容量耗尽时拒绝新执行；无法保留的
  超大结果转成 `RESULT_UNKNOWN` 墓碑，后续重放仍不会重新执行副作用。
- 账本只覆盖当前 Remote Extension Host 生命周期。Controller 在 transport 断开后
  自动查询状态并恢复原调用仍是下一独立目标；当前不得因为查询不可达而自动重放。
- OpenSSH 回退没有远端结果账本或 `resultStatus`，本次支持声明只针对
  `vscode-remote` transport。

## 遗留风险与结论

- 待补测：安装当前候选后，从官方 Codex UI 发起同一远端副作用调用的重送和状态查询，
  核对 Codex 日志、Bridge 审计、Remote Executor 返回和副作用计数。
- 待补测：Linux 与 Windows Remote SSH 的断线、重连、窗口关闭和 Extension Host
  重启边界。
- 已知限制：Controller 尚未在 transport 断开后自动调用 `resultStatus` 恢复原调用。
- 已知限制：账本不跨 Remote Extension Host 重启持久化；OpenSSH 回退没有远端账本。
- 最终结论：稳定幂等键、当前 Extension Host 内有界结果账本和显式状态查询已通过
  自动化与双平台构包，当前可作为自动化候选；真实 Remote SSH 断线恢复仍未完成，
  也不得声明为已通过。
