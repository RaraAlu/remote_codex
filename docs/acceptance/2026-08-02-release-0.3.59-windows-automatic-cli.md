## 实现与安全边界

- Windows 解析 PATH/PATHEXT 后，只有同一 npm 目录中的 extensionless、CMD、PowerShell
  三个入口全部存在且均为普通文件时才允许接管；不完整集合、非文件和备份碰撞失败关闭。
- 首次启用把三个原始 wrapper 原样移动到
  `.codex-remote-bridge-original[.cmd|.ps1]`，再安装调用稳定
  `codex-vscode.exe automatic-cli` 的受管 wrapper。v3 元数据记录每个启动器及备份路径，
  Shim 只把内部 `automatic-cli` 子命令解释为普通入口。
- 无参数调用只附着工作目录完全一致的唯一活动会话；无匹配时运行备份的官方 CLI；多个
  同目录会话继续失败关闭。任意带参数调用直接透传官方 CLI，显式
  `codex-vscode.exe` 行为保持不变。
- 停用时只覆盖仍与 Bridge 受管内容完全一致的文件；当前文件已被 npm 或用户修改时保留
  外部版本并清理陈旧备份。npm 升级覆盖 wrapper 后，下一次扩展初始化把新 wrapper 刷新
  到备份，再恢复受管入口。

## 遗留风险与结论

- 当前 Windows 环境没有 Git Bash，extensionless shell wrapper 已验证内容、备份、恢复与
  自动化，但未在真实 Git Bash 中启动；PowerShell 和 CMD 均已实测。
- 多个同目录活动会话的歧义失败关闭由单元测试覆盖，本轮没有为实机样本伪造第二个官方
  活动任务描述符。
- 官方扩展 `26.727.40816` 的 Windows Remote SSH `git-init-watcher ENOENT` 噪声、完整
  Windows M01-M11、双平台 stage 收集、量化门禁和 Windows SEA Authenticode 仍是独立 TODO。
- 最终结论：Windows npm 三种普通入口的可回滚接管、唯一同目录会话自动附着、无匹配
  透传、参数透传、停用恢复和真实 npm 覆盖恢复在 `0.3.59` **限定范围通过**。本记录不
  构成 `0.4.0` 发布或完整双平台支持声明。
