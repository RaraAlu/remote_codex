## 问题与修复边界

- 设置恢复后，`openai.chatgpt` 不在当前 UI Extension Host 可见范围，
  `chatgpt.cliExecutable` 配置项也尚未注册。
- 首个 `0.3.9` 候选先成功写入 `remote.extensionKind.openai.chatgpt=["ui"]`，但在同一
  Extension Host 继续写 `chatgpt.cliExecutable`，VS Code 因该配置尚未注册而拒绝。
  该版本随即废弃，修复后的行为改用 `0.3.10`。
- `0.3.10` 把设置应用拆成明确阶段：若 UI 路由缺失，只写入 extension kind、校验
  有效值并请求重载；新 Extension Host 注册官方配置后，再写入 Shim 并完成下一次重载。
- Controller 在设置完整前不解析官方运行时、不启动 VS Code transport 或写窗口会话；
  交互配置会重新启用 `autoInitialize`，配置变化产生的重入初始化会延迟到当前阶段结束。
- 本目标不安装远端 Codex，不改变 Shim、Executor、远端工具、MCP 或权限协议。
