## 变更与边界

| 项目 | 内容 |
| --- | --- |
| Bridge 版本 | `0.3.22` |
| 基线提交 | `3c78b4f` |
| Remote Executor | `0.2.13`；诊断协议 8，未改变 |
| 新流程 | `package:stage`、`package:collect`、`package:verify` |
| `package:all` | 只收集标准路径中的两个原生 stage，不再跨平台构建 |
| 声明范围 | 流程自动化和 Linux x64 原生 stage；Windows stage 与最终双端收集待补测 |

- `npm run package` 只构建当前主机的原生 Controller；传入旧 `all` 模式会明确拒绝，
  不再依赖预存的异平台启动器。
- Linux x64 与 Windows x64 分别运行 `npm run check` 和 `npm run package:stage`。
  stage 清单绑定来源平台、x64 架构、Controller/Executor 版本、文件大小和 SHA-256。
- 收集器不只信任清单：它重新解析两个 Controller VSIX 的包元数据，要求
  `extensionKind=["ui"]`，核对 Windows 只含 `.exe`、Linux 只含 `.cjs`，并解析内嵌
  Executor VSIX 的版本、`extensionKind=["workspace"]` 和实现摘要。
- 两个 stage 的 Executor ZIP 时间戳可以不同，但内嵌 `extension.cjs` 实现摘要必须
  一致。最终版本化 Executor 与无版本副本必须逐字节一致。
- 收集器先在 `dist/` 下的临时目录复制并完成全部验证，再更新正式文件；随后只保留
  当前版本双平台 Controller、匹配的版本化 Executor 和无版本副本。
- `artifacts/` 被 Git 与三个 VSIX ignore 清单排除，stage 清单和收集材料不会进入
  Controller 包。
