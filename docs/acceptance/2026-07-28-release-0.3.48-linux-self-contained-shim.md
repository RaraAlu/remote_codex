## 问题证据

- 原 Linux Controller 只分发带 `#!/usr/bin/env node` 的
  `dist/codex-bridge-shim.cjs`。
- 本机没有系统 Node 时，官方 Codex 日志记录
  `/usr/bin/env: "node": 没有那个文件或目录`，app-server 以退出码 `127` 结束；
  Bridge 的远端 Executor 已连接，但官方面板持续加载。
- 用户安装用户级 Node 后，相同 CJS 能返回内置 Codex 版本，确认失败位于 Shim 入口，
  与远端 Linux ARM64 Executor 无关。

## 修复

- Linux x64 与 Windows x64 使用同一 Node SEA 构建函数；Linux 生成无脚本后缀的
  `dist/codex-bridge-shim` ELF，Windows 继续生成 `.exe`。
- Linux VSIX 只包含自包含 ELF，排除 CJS 和 source map；Windows VSIX 同时排除 Linux
  ELF 和 CJS，平台包校验拒绝混装或退回脚本入口。
- Controller 的内容寻址安装选择 Linux ELF。旧 `codex-bridge-shim.cjs` 路径仍识别为
  Bridge 托管入口，以便升级时迁移而不污染用户设置备份。
- npm `bin` 使用的 CJS 中间产物保持不变；本目标只改变官方扩展通过
  `chatgpt.cliExecutable` 启动的 VSIX 平台入口。
