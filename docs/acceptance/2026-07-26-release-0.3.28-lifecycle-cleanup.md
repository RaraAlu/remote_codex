| 命中的升级触发项 | Controller/Shim、Remote Executor 能力、stdio 生命周期、VS Code Remote SSH 重载 |

- Remote Executor 在 Linux 终止进程组前从 `/proc` 捕获完整后代树，并在强制终止阶段
  保留这份 PID 集合。即使 MCP 子进程再次创建独立进程组，也会被一并终止。
- Executor 新增 `stdioProcessTreeStop` 和 `stdioDetachedDescendantStop` 能力。
  Controller 只按实际能力集合触发升级，不按版本号准入；`0.2.13`、`0.2.14` 因缺少
  当前必需能力而自动升级到 `0.2.15`。
- MCP relay 在 transport 关闭后移除监听并暂停输入流，避免 TTY `stdin` 继续保持
  Node 事件循环。
- Controller 的 `deactivate` 等待 transport、远端 stdio、会话文件和 Unix socket
  清理完成，不再只触发未等待的异步回收。

## 缺陷复现与版本演进

### `0.3.26` / Executor `0.2.13`

- 重载前：远端前台 PID `42225`、后台 PID `42164`、CodeGraph 主进程 `42179`、
  子进程 `42189`，本地 relay PID `1138187`。
- 重载后前后台命令终止，但 CodeGraph 子进程以 `PPID=1` 留存，本地 relay 继续使用
  旧会话配置。该样本判定失败。
- 根因分别是 Executor 只终止直接子进程，以及 relay 只处理 socket `end/error`。

### `0.3.27` / Executor `0.2.14`

- 增加独立进程组终止和 socket `close` 处理后，主动停止探针仍发现 CodeGraph 子进程
  自行 `setsid` 并以 `PPID=1` 留存。`0.2.14` 已实际安装，因此没有在同一版本下改变
  行为，而是继续推进 Executor。

### `0.3.27` / Executor `0.2.15`

- 主动停止前 CodeGraph 主/子进程为 `2`，停止后为 `0`；本地探针 relay 为 `0`。
- 窗口重载前，远端后台 PID `64452`、CodeGraph PID `64468/64478`、前台 PID
  `64516`，本地 relay PID `1170904`。
- 重载后远端生命周期标记进程为 `0`，CodeGraph 为 `0`，前台请求明确返回
  `REMOTE_TRANSPORT_DISCONNECTED`。
- 但本地 relay 已失去 socket 后仍因 TTY `stdin` 留存，旧 socket 文件也没有删除。
