## 根因与实现

- 官方 `openai.chatgpt` 扩展运行在本地 UI Extension Host。文件引用目标为远端 POSIX
  绝对路径时，其打开处理会构造本机 `file:` URI；目标为相对路径时则以当前
  `vscode.workspace.workspaceFolders[0].uri` 解析，能够保留 `vscode-remote` scheme。
- 修复只投影 `agentMessage.text` 中位于规范远端主根内的 Markdown link target。
  单行、行列、行范围和 `#L` 位置后缀均保留；含空格的 angle-bracket target 和 title
  也受支持。
- 投影同时覆盖实时 server message 和 `thread/read` 返回的历史嵌套 item。普通绝对
  路径文字、inline/fenced code、用户消息、根外路径和本地次级根失败关闭，不改写。
- Remote SSH thread 策略新增工作区相对文件引用要求，减少新回答先生成绝对目标再由
  Shim 兜底的情况。

## Remote SSH 实机

- 强制安装 `codex-remote-bridge-0.3.50-linux-x64.vsix` 后，用户重载活动 `g1_1`
  Remote SSH 窗口。Controller 把托管入口迁移到
  `0.3.50-ff3e478358a4aa80/codex-bridge-shim`。
- Bridge 在 `2026-07-30T03:29:01.064Z` 连接活动 transport 并因等待 app-server
  initialize 进入 `degraded`，在 `03:29:01.315Z` 进入 `ready`。审计记录
  `shimStarted=true`，连接根为 `/home/unitree/mimiclite-sim2real`。
- 官方 app-server 在窗口重载后完成两个 initialize 请求，并成功恢复 thread
  `019fb0ea-1849-7071-8c4b-e0d37f387dbd`。恢复前点击绝对目标会记录
  `Failed to handle absolute path`；`0.3.50` 重载后没有新增同类错误。
- 用户在恢复后的官方 Codex 对话中手动点击文件引用选框，确认 VS Code 成功跳转到远端
  文件及引用位置。该动作由官方扩展通过当前远程 workspace URI 完成，不需要新增
  Bridge 文件操作；Bridge 审计在点击期间保持当前远端会话和 `ready` 状态。
- 官方扩展仍持续记录既有的 `git-init-watcher ENOENT`，因为本地 UI Extension Host
  尝试直接监视远端 POSIX workspace path。本修复没有伪造 workspace URI；该警告与
  文件引用打开路径独立，未影响本次点击验收。
