## 根因与实现

远端代理和 VS Code Server 环境刷新后，一次普通重载仍记录 `9,860 ms` Executor 能力
探测和约 `6.58 s` Remote Extension Host 无响应。远端日志显示，内置
`GitHub.copilot-chat` 由 `onChatSession:copilotcli` 先于 Executor 激活并占用约
`10.42 s`。关闭 Copilot CLI 后台会话只把首轮探测降至 `1,114 ms`，随后
`copilot-cloud-agent` 又激活同一扩展并产生约 `14.4 s` 后置阻塞，因此停用单个功能入口
不是完整修复。

把 `remote.extensionKind.GitHub.copilot-chat` 设为 `[ui]` 后，试验重载的 Executor
能力探测为 `239 ms`，远端不再生成 Copilot 日志目录。最终实现同时管理
`openai.chatgpt` 与 `GitHub.copilot-chat` 的 `[ui]` 映射；v3 快照分别保存两项原值，
恢复时只还原这两项并保留其他映射，旧 v1/v2 快照会迁移。Copilot 本体、后台会话和云端
会话均未被停用。

## 遗留风险与结论

- `remote.extensionKind` 是当前 VS Code 用户配置下的全局放置覆盖；Bridge 停用恢复会按
  首次接管快照恢复两项受管映射，不会关闭 Copilot。
- Linux Controller 和完整 M01-M11 不由本记录替代，继续由 Windows M13 和最终 `0.4.0`
  门禁跟踪。
- 最终结论：Windows Copilot 远端宿主阻塞修复通过，连续稳定门禁为 3/3；根 README 中
  对应 Windows 更新环境 TODO 可以关闭。
