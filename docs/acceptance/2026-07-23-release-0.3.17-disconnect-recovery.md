## 实现与结果语义

- `VsCodeRemoteExecutor` 仅在已标记为有副作用的调用因 transport 中断得到
  `RESULT_UNKNOWN` 时进入恢复；原 `execute` 请求永远不会自动重发。
- 恢复请求使用原幂等键建立新 socket 调用 `resultStatus`。状态查询自身若短暂断开，
  会在三秒有界窗口内再次连接；running 状态也在同一窗口内轮询。
- completed 返回账本中的原命令结果并标记 `idempotencyOutcome=replayed`；
  cancelled/failed 还原原错误，并记录恢复尝试次数。
- unknown、状态查询持续不可达、账本响应缺少终态负载或恢复窗口结束时返回
  `RESULT_UNKNOWN`。这些分支都不会重放原命令，也不会回退到本地或 OpenSSH。
- 该恢复只覆盖当前 Remote Extension Host 代次的有界账本。Extension Host 已重启、
  账本已过期或 transport 描述符整体失效时，结果保持未知。

## 遗留风险与结论

- 待补测：安装当前候选后，在真实 Remote SSH 中分别制造 completed、cancelled、
  failed、running 和 unknown 状态的 transport 中断，核对恢复耗时、原结果和副作用数。
- 待补测：Linux 与 Windows 的窗口关闭、Controller 停止、Remote Executor 失联和
  Extension Host 重启边界。
- 已知限制：账本不跨 Remote Extension Host 重启持久化；旧 transport 描述符整体失效
  时无法建立查询 socket，只能返回 `RESULT_UNKNOWN`。
- 已知限制：OpenSSH 回退没有远端账本或状态查询，本次恢复只适用于
  `vscode-remote` transport。
- 最终结论：断线后的新 socket 状态查询、终态恢复和未知结果失败关闭已通过自动化与
  双平台构包，当前可作为自动化候选；真实 Remote SSH 和双平台生命周期仍不得声明
  通过。
