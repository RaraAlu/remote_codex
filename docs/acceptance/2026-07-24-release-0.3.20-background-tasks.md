## 变更与边界

| 项目 | 内容 |
| --- | --- |
| Bridge 版本 | `0.3.20` |
| 基线提交 | `f190aaa` |
| Remote Executor | `0.2.13`；诊断协议 8 |
| 新能力 | `backgroundStart`、`backgroundStatus`、`backgroundLog`、`backgroundCancel` |
| 命中的触发项 | Controller/Shim、Remote Executor 协议、审批、安全策略和生命周期 |
| 声明范围 | Linux 本地自动化、进程组等价执行与 Linux 构包；真实候选窗口和 Windows 待补测 |

- 后台任务只支持非交互命令，且只在活动 VS Code Remote transport 上开放；OpenSSH
  回退明确返回 `COMMAND_DENIED`，不伪装具有跨调用生命周期。
- 任务按远程工作区和稳定任务 ID 隔离。同 ID 同参数合并或回放，不同参数失败关闭；
  transport 丢失启动响应后只查询任务状态，不重发命令。
- 每个 Extension Host 最多登记 8 个任务；每项最多保留 4 MiB stdout/stderr，单次最多
  读取 256 KiB，终态保留 15 分钟，任务寿命默认 1 小时、上限 24 小时。
- 工作目录同时经过词法和 `realpath` 根边界检查。继承环境移除 Codex、OpenAI、
  VS Code 和应用凭据；显式环境变量仍校验名称。
- 启动沿用 thread 权限模式和官方命令审批；`full-access` 自动放行。审计只记录任务 ID、
  状态、游标和审批结果，不记录 argv 输出、日志正文或环境值。
- 取消和超时先终止 POSIX 进程组；Extension Host 关闭时同步发送 TERM/KILL，避免留下
  脱离 Executor 的无主进程。
- 本地调用客户端、Shim 或 Controller transport 断开不会自动终止已登记任务；任务继续
  到终态、超时或显式取消。窗口关闭、Executor 停用或 Extension Host 退出才执行统一
  进程组清理。
