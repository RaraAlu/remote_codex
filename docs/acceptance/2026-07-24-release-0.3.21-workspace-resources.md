## 变更与边界

| 项目 | 内容 |
| --- | --- |
| Bridge 版本 | `0.3.21` |
| 基线提交 | `2fcceee` |
| Remote Executor | `0.2.13`；诊断协议 8，未改变 |
| 新工具 | `workspace_open_file`、`workspace_show_diff` |
| Controller 操作 | 资源登记、编辑器打开、VS Code Diff |
| 声明范围 | Linux 本地自动化和 Linux 构包；真实候选界面与 Windows 待补测 |

- 稳定资源 URI 使用 `codex-bridge` scheme，并绑定 host、根 ID、目标端和根内相对路径；
  不包含会话令牌、绝对根路径或文件正文。
- Shim 先经对应工作区执行器获得规范路径，再把资源登记请求送入已认证 Controller
  transport。OpenSSH 模式没有编辑器 transport，显式失败关闭。
- Controller 对远端文件复用当前窗口实际打开的 `vscode-remote` 工作区 URI，不改写、
  替换或合成工作区根 URI；本地文件只允许仍在配置中且未撤销的授权次级根。
- 内容提供器只接受当前 Controller 会话登记过的资源。每次读取重新核对活动 host、
  Remote SSH 根和本地授权，伪造 URI、根变化、撤销授权和过期快照均明确失败。
- 远程 POSIX 路径不再投影成官方协议中的本地 `read`、`listFiles` 或 `search` 路径动作；
  编辑器跳转只通过 `workspace_open_file` 的实际远程 URI 完成。
- Diff 左端是最多 1 MiB 的完整 UTF-8 旧内容，必须与 `workspace_read_file` 返回的
  SHA-256 一致；快照只在内存中有界保留。右端使用当前工作区实际 URI。
- 审计只记录路径、hash、标题、资源身份和操作结果，不记录 Diff 正文或文件内容。
