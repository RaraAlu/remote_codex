## 问题与修复边界

- `0.3.5` 及更早版本在官方 stdio 结束时直接对外部 WebSocket 和官方上游调用
  `terminate()`。真实外部客户端因此报告
  `Connection reset without closing handshake`，无法区分正常重载和异常断线。
- `0.3.6` 对所有外部客户端发送关闭码 `1012` 和原因
  `Bridge app-server restarting`，等待最多 250 毫秒；只有未完成握手的连接才强制终止。
- 外部连接完成关闭后，官方上游使用 `1001 / Bridge client input closed` 正常关闭，
  再终止 app-server 子进程。最终清理逻辑复用同一正常关闭路径。
- 本目标不增加自动重连或跨重连幂等账本，也不改变工具、权限、Executor 或 MCP 路由。

## Linux x64 实机证据

- 第一次手动重载后，活动 Shim 为
  `0.3.6-8c377032ff9a6761/codex-bridge-shim.cjs`，Bridge 从 `connecting` 恢复
  `ready`。观察器经当前 loopback 网关鉴权并完成 `initialize`。
- 用户第二次手动重载时，观察器输出
  `{"event":"close","code":1012,"reason":"Bridge app-server restarting","sawError":false}`；
  没有 WebSocket protocol error，也没有输出任何令牌。
- 旧 Shim PID `499740` 随后退出；`499740.json`、`499740.token` 和
  `499740.upstream.token` 均被删除。Bridge 审计写入该观察器的成功 disconnect。
- 新 Shim PID `502998` 使用相同规范远端根 `/home/unitree/rl_sar`，Bridge 在约
  4.726 秒内重新进入 `ready`，新的 app-server 能完成 `initialize` 和 `thread/list`。

## 遗留风险与结论

- 重载后 `thread/list` 能列出一个 `notLoaded` 历史 thread，但显式恢复该 thread 返回
  `thread not found`。该现象不影响本次关闭握手结论，需作为独立的历史 thread 恢复
  兼容性问题分析。
- `Codex Bridge: Restore Official Settings`、显式停止、Extension Host 完全退出、
  relay/MCP 子进程归零和 Windows x64 实机仍待补测。
- 最终结论：`0.3.6` 的外部网关正常关闭目标在 Linux x64 真实 Remote SSH 重载链路
  通过；完整生命周期与双平台支持仍受上述待补门禁限制。
